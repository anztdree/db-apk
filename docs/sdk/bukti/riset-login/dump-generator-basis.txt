BASIS BUKTI GENERATOR TOKEN LOKAL (koreksi Tahap B — generate, bukan sisa jejak)
Tanggal: 2026-10-20 | Sumber: classes.dex APK original (bedah androguard)
Pertanyaan: apakah rantai klien MEMVALIDASI isi token? Jawaban: TIDAK — token opaque.

=== 1. QGUserData.generateFromJson (bean sesi SDK) ===
Field yang dibaca (urutan dex):
  username  : getString          (WAJIB — tanpa = exception)
  uid       : getString          (WAJIB)
  displayUid: has()? getString : ""   (opsional)
  token     : getString          (WAJIB)
  isGuest   : getString, equals("1")  (WAJIB; "1" = guest)
  openType  : optString          (opsional)
  isNewUser : opt                (opsional)
  isTrash   : optInt             (opsional)
→ TIDAK ADA pemeriksaan isi/format/panjang/signature token. Disimpan apa adanya.

=== 2. Parser sesi SDK (psalmicvolleyball.cointhreat.cointhreat(String)) ===
- Input: string JSON dari respons endpoint user/*
- Pre-cek HANYA pada string input: isEmpty / equalsIgnoreCase("[]") / ("{}")
- Field dibaca:
  checkRealName : opt, default "0"
  authToken     : getString  (WAJIB) → disimpan apa adanya (TANPA validasi isi)
  tips          : has()? → getString (opsional)
  userData      : getJSONObject → QGUserData.generateFromJson
  bindInfo      : optJSONObject → QGUserBindInfo.generateFromJson
→ authToken = string OPAQUE. Tidak ada dekode, tidak ada MD5, tidak ada cek format.

=== 3. Pemakai token setelah sesi (game) ===
onLoginFinished: HashMap {uid, username, token, usermode} ← semua langsung dari bean,
tanpa transformasi. Token dikirim ke gerbang via GET query (?token=...) apa adanya.

=== 4. Pemeriksaan gerbang oleh game (Runnable pursetruechild.nationalcommunitymissing.run) ===
- Respons disimpan utuh ke field holder (pursetruechild) SEBELUM di-parse.
- Parsing: new JSONObject(respons) → getInt("code")
    code == 0  → LOLOS (tidak ada field lain yang dibaca di jalur ini)
    code != 0  → has("msg")→dialog(msg); else has("message")→dialog(message); return
  parse gagal (exception) → MainActivity.customreading(); return
  respons null/kosong → dialog R.string.check_network
- Log tag: "sdk登录验证url" (sebelum GET) / "sdk登录验证返回：" (sesudah).

=== 5. Konsumen lanjutan respons gerbang (di luar runnable) ===
MainActivity.hardlinerspare (dispatcher event JS "游戏客户端事件"):
  - membaca ulang field holder (respons gerbang utuh) 2×
  - ironoriginhoblike.put(kunci, respons-utuh)  → payload event startGame/startTsGame
  - juga put: reweavingsiamesedpropertylessnesses() (≈loginServer) dan singersmooth()
    (≈loginKey) dari holder pursetruechild
→ Respons gerbang DITERUSKAN KE JS. Konsekuensi: jawaban gerbang lokal sebaiknya
  mempertahankan BENTUK 10 field live (code/sdk/nickName/loginToken/userId/sign/
  sdkType/osType) dengan nilai generate baru. Validasi sign/loginToken di sisi JS
  (main.min.js) BELUM dibedah → dicatat sebagai risiko R1' (di luar pintu gerbang).

=== 7. Kesimpulan ===
Token/authToken = string opaque di SELURUH rantai klien (SDK + game + gerbang).
Pemegang server-lah yang menentukan nilai token. Server lokal = pemegang baru
→ MENGGENERATE token baru SAH secara struktur. Tidak ada kebutuhan sisa jejak panen.
Format @angka@ (nilai 92–221) adalah format internal server asli (klien tidak pernah
mendekode) → generator default cukup md5/heksa acak; opsi gaya @..@ bisa lewat config.
